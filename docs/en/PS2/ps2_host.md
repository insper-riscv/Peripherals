# PS/2 physical layer (`ps2_host`)

## 1. What it is

`ps2_host` is the host-side physical layer of one PS/2 channel. It receives frames from a keyboard or a mouse, sends commands to the device, and hands the rest of the hardware only bytes and status pulses. Each instance is independent, with no shared state and no global signal.

## 2. Channels and the Y cable

The DE0-CV has a single PS/2 connector. With one device it uses channel 0. For a keyboard and a mouse at the same time, a Y cable splits the connector, and the second device uses channel 1, which the board manual reserves for that purpose.

| Channel | Device | Clock | Data |
| :--- | :--- | :--- | :--- |
| 0 | Keyboard | `PS2_CLK` (D3) | `PS2_DAT` (G2) |
| 1 | Mouse | `PS2_CLK2` (E2) | `PS2_DAT2` (G1) |

Each channel has its own `ps2_host` instance, and the two run side by side.

## 3. Interface

| Port | Direction | Meaning |
| :--- | :--- | :--- |
| `i_clk`, `i_rst_n` | input | System clock and active-low reset |
| `io_ps2_clk`, `io_ps2_dat` | bidirectional | Open-drain lines of the connector |
| `o_rx_data` (8 bits), `o_rx_valid` | output | Byte received with correct parity, one `o_rx_valid` pulse per byte |
| `o_rx_error` | output | Pulse on a parity, frame, acknowledge or timing error |
| `i_tx_data` (8 bits), `i_tx_valid` | input | Command to send to the device |
| `o_tx_ready` | output | The transmitter accepts a new byte |

| Generic | Default | Meaning |
| :--- | ---: | :--- |
| `filter_cycles` | 8 | Cycles a line level must last to pass the glitch filter |
| `inhibit_cycles` | 6000 | Cycles with the clock at `0` before sending (120 us at 50 MHz, above the 100 us minimum) |
| `timeout_cycles` | 1000000 | Cycles without a clock edge that abort a frame (20 ms at 50 MHz) |

The defaults assume a 50 MHz clock. The reset must last at least two cycles so the synchronizer loads the level of the lines.

## 4. Line input

Each line goes through a two-stage synchronizer and a glitch filter that accepts a new level only after `filter_cycles` consecutive cycles. The pins are open-drain: the module only holds a line at `0` or releases it, and the pull-up resistor on the board takes the line to `1`.

## 5. Reception

The device generates the clock. The frame has 11 bits, sampled on each falling edge of the filtered clock.

| Bit | Content |
| :--- | :--- |
| 0 | Start, always `0` |
| 1 to 8 | Data, least significant bit first |
| 9 | Odd parity |
| 10 | Stop, always `1` |

Odd parity makes the total number of `1` bits among the data and the parity odd. A correct frame produces a one-cycle `o_rx_valid` pulse with the byte on `o_rx_data`. A frame with an invalid start, parity or stop produces an `o_rx_error` pulse, and the module returns to idle. A frame stalled for `timeout_cycles` cycles also produces the error pulse and is abandoned.

## 6. Transmission

A byte is accepted in the cycle in which `i_tx_valid` and `o_tx_ready` are both `1`. The transmitter waits for the line to be free and then follows the steps below.

1. Holds the clock at `0` for `inhibit_cycles` cycles.
2. Holds the data at `0` (start bit) and releases the clock.
3. On each falling edge of the clock generated by the device, puts one bit of the byte on the data line (least significant first), and then the odd parity.
4. Releases the data line and waits for the device to pull it low as the acknowledge.

If the acknowledge is missing or the clock stops for `timeout_cycles` cycles, the module releases the lines and produces an `o_rx_error` pulse. `o_tx_ready` is `0` while a frame arrives or a send is in progress.

## 7. Verification

The entity tests use a testbench with two `ps2_host` instances, one per channel, and cover set 2 make, break and extended frames, parity, stop and start errors, a stalled frame, a short glitch, commands with and without acknowledge, a command deferred during a reception, and both channels active at the same time without interference.
