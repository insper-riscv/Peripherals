# LTC2308 A/D converter controller (DE10-Nano and DE0-Nano-SoC)

🌐 [Português](../../pt-br/ADC/ltc2308.md) · [English](../../en/ADC/ltc2308.md)

## 1. What it is

Bus controller of the eight-channel, 12-bit A/D converter of the DE10-Nano and DE0-Nano-SoC boards. A sweep machine (`adc_sweep`, the same as the ADC128S022) asks the chip for one frame per channel, in order, and stores the result of each channel in a 12-bit register. Each frame has the ADC_CONVST pulse, the wait for the conversion and a 12-bit SPI word with the channel configuration.

| Block | Role |
| :--- | :--- |
| `spi_master` | One-word SPI master, here in mode 0 with 12-bit words |
| `adc_sweep` | Sweep of the eight channels, channel registers, status, divider and interrupt |
| `ltc2308` | Top with the ADC_SDO synchronizer, the CONVST pulse, the waits and the configuration word |

## 2. Pins and boards

The manuals of both boards (section 3.6.4 of each, table 3-12) wire the converter to four FPGA pins, with Cyclone V device pin numbers, so the controller in the FPGA owns the protocol. There is no processor between the FPGA and the converter. The analog inputs ADC_IN0 to ADC_IN7 go to the 2x5 header, and ADC_IN0 to ADC_IN5 also go to the Arduino header.

| Peripheral port | Direction | Name in the manual | FPGA pin (DE10-Nano and DE0-Nano-SoC) | Manual description |
| :--- | :--- | :--- | :--- | :--- |
| `o_adc_convst` | output | `ADC_CONVST` | `PIN_U9` | Conversion start |
| `o_adc_sck` | output | `ADC_SCK` | `PIN_V10` | Serial data clock |
| `o_adc_sdi` | output | `ADC_SDI` | `PIN_AC4` | Data from the FPGA to the converter |
| `i_adc_sdo` | input | `ADC_SDO` | `PIN_AD4` | Data from the converter to the FPGA |

All at 3.3 V, and both manuals carry the same table. The DE10-Nano manual states in section 5.2 that the FPGA reads the converter over a serial interface and that the input voltage goes from 0 to 4.096 V, so each code is worth 1 mV. The manual gives 500 ksps and an SCK of up to 40 MHz.

## 3. Parameters and ports

| Parameter | Default | Meaning |
| :--- | ---: | :--- |
| `clock_hz` | 50000000 | Module clock frequency, in hertz |
| `sclk_hz` | 10000000 | ADC_SCK frequency after reset, in hertz |
| `convst_ns` | 100 | Width of the high pulse of ADC_CONVST, in nanoseconds |
| `conversion_ns` | 1600 | Wait for the conversion after the pulse, in nanoseconds |
| `acquisition_ns` | 300 | Wait for the acquisition after the frame, in nanoseconds |
| `channel_latency` | 1 | Frames between configuring a channel and receiving its result (0 or 1) |

Each time becomes $\lceil t \cdot clock\_hz / 10^9 \rceil$ cycles. The bus ports are `i_clk`, `i_rst`, `i_write`, `i_address` (4 bits), `i_data_in`, `o_data_out` and `o_irq`, plus the four pins of section 2. The register map is that of `adc_sweep`, described in [adc128s022.md](adc128s022.md) (section 5): `CH0` to `CH7` at words 0 to 7, `CONTROL` at 8, `STATUS` at 9 and `DIVIDER` at 10.

## 4. Frame

A frame has three steps.

| Step | What happens |
| :--- | :--- |
| 1 | ADC_CONVST rises, stays high for `convst_ns`, and then falls |
| 2 | The controller waits `conversion_ns` |
| 3 | A 12-bit SPI word in mode 0 (ADC_SCK idle low, the chip changes ADC_SDO on the falling edge and the controller samples on the rising edge), most significant bit first, and then the wait of `acquisition_ns` |

The word sent on ADC_SDI starts with the six configuration bits S/D, O/S, S1, S0, UNI and SLP and ends with six zeros. The configuration is single-ended (S/D at 1), unipolar (UNI at 1) and with no sleep (SLP at 0), and O/S, S1 and S0 form the channel index.

$$ \text{channel} = 4 \cdot S1 + 2 \cdot S0 + O/S $$

The word received on ADC_SDO is the 12-bit result. With `channel_latency` at 1 the result of a frame is that of the configuration of the previous frame, so the sweep has 9 frames (one to prime).

### 4.1. Origin of each parameter

The LTC2308 datasheet is not in the repository, so only what the manual says is confirmed.

| Item | Origin |
| :--- | :--- |
| Four pins on the FPGA side, 12 bits, 8 channels, 500 ksps, SCK up to 40 MHz, input of 0 to 4.096 V | Confirmed by the DE10-Nano and DE0-Nano-SoC manuals (sections 3.6.4 and 5.2) |
| Mode 0, order of the six configuration bits, channel encoding | Not confirmed; assumption of the controller and of the test model |
| One-frame delay between configuration and result | Not confirmed; the `channel_latency` parameter lets it be changed |
| CONVST pulse, conversion and acquisition times | Not confirmed; conservative values in the parameters |

## 5. Use by software

The C example runs one sweep and converts channel 0 to millivolts. With the 0 to 4.096 V range of the manual, the code in millivolts is the code read itself.

```c
#include <stdint.h>

/* Base of the peripheral, defined by the platform. */
#define ADC_BASE ((volatile uint32_t *)0x40001000u)

enum { CH0 = 0, CONTROL = 8, STATUS = 9, DIVIDER = 10 };
enum { ENABLE = 1u << 0, START = 1u << 2 };
enum { SWEEP_DONE = 1u << 1 };

/* Sweep the eight channels once and wait for the end. */
void adc_sweep_once(void)
{
    ADC_BASE[STATUS] = SWEEP_DONE;
    ADC_BASE[CONTROL] = START;
    while ((ADC_BASE[STATUS] & SWEEP_DONE) == 0) {
    }
}

/* Return the voltage of the channel (0 to 7), in millivolts. Range 0 to 4.096 V. */
uint32_t adc_millivolts(unsigned channel)
{
    return ADC_BASE[CH0 + channel] & 0xFFFu;
}
```

## 6. Verification

The entity test connects the controller to a converter model that decodes the configuration of each frame, checks the ADC_CONVST pulse and the conversion time before the first clock, and returns eight known voltages. The cases cover the idle pins, the single sweep with the nine frames and the six configurations, the reading of each voltage and the continuous sweep that follows a changing voltage. The model repeats the assumptions of section 4.1 and marks them in the code. The formal proof checks the frame (pulse width and conversion wait, clock idle low, 12 edges, channel configuration on ADC_SDI, completion pulse) and, in `adc_sweep`, the sweep machine, with mutants it must reject. Reading with a voltage on channel 0 on the board depends on a bench test.
