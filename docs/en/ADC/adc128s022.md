# ADC128S022 A/D converter controller (DE0-Nano)

🌐 [Português](../../pt-br/ADC/adc128s022.md) · [English](../../en/ADC/adc128s022.md)

## 1. What it is

Bus controller of the eight-channel, 12-bit A/D converter of the DE0-Nano. A sweep machine (`adc_sweep`) asks the chip for one 16-clock SPI frame per channel, in order, and stores the result of each channel in a 12-bit register. The software only reads the registers `CH0` to `CH7`, without driving the SPI.

| Block | Role |
| :--- | :--- |
| `spi_master` | One-word SPI master, here in mode 3 with 16-bit words |
| `adc_sweep` | Sweep of the eight channels, channel registers, status, divider and interrupt |
| `adc128s022` | Top with the ADC_SDAT synchronizer, the chip select and the channel address word |

## 2. Pins and board

The DE0-Nano manual (section 3.6, table 3-9) lists the four pins of the converter. The analog inputs IN0 to IN7 go to the 2x13 header (figures 3-10 and 3-11 of the same section).

| Peripheral port | Direction | Name in the manual | FPGA pin | Manual description |
| :--- | :--- | :--- | :--- | :--- |
| `o_adc_cs_n` | output | `ADC_CS_N` | `PIN_A10` | Chip select |
| `o_adc_saddr` | output | `ADC_SADDR` | `PIN_B10` | Digital data input of the converter |
| `i_adc_sdat` | input | `ADC_SDAT` | `PIN_A9` | Digital data output of the converter |
| `o_adc_sclk` | output | `ADC_SCLK` | `PIN_B14` | Digital clock input of the converter |

All at 3.3 V. The manual gives the conversion rate of 50 to 200 ksps and the 0 to 3.3 V range of the reading demonstration (section 8.3).

## 3. Parameters and ports

| Parameter | Default | Meaning |
| :--- | ---: | :--- |
| `clock_hz` | 50000000 | Module clock frequency, in hertz |
| `sclk_hz` | 3200000 | ADC_SCLK frequency after reset, in hertz |
| `channel_latency` | 1 | Frames between addressing a channel and receiving its result (0 or 1) |

The reset divider is $\lceil clock\_hz / (2 \cdot sclk\_hz) \rceil - 1$, which keeps ADC_SCLK at `sclk_hz` or below. With 16 clocks per conversion, the 50 to 200 ksps range of the manual corresponds to

$$ f_{SCLK} = 16 \cdot f_{sample} \in [0.8 ; 3.2] \ \text{MHz} $$

The bus ports are `i_clk`, `i_rst`, `i_write`, `i_address` (4 bits), `i_data_in`, `o_data_out` and `o_irq`, plus the four pins of section 2. The block window takes 11 words and reads have no side effect.

## 4. SPI frame

Each frame is a 16-bit word in mode 3 (ADC_SCLK idle high, the chip changes ADC_SDAT on the falling edge and the controller samples on the rising edge), most significant bit first, with ADC_CS_N low during the frame.

| Bits | On ADC_SADDR (controller to chip) | On ADC_SDAT (chip to controller) |
| :--- | :--- | :--- |
| 15:14 | don't care (zero) | zero |
| 13:11 | channel address (ADD2 to ADD0) | zero (the first two) and then the 2 high bits of the result |
| 10:0 | don't care (zero) | result, down to bit 0 |

The received word has four zeros and the 12-bit result in bits 11:0. With `channel_latency` at 1 the result of a frame is that of the channel addressed in the previous frame, so the sweep has 9 frames (one to prime) and the result of frame $f$ goes to channel $f - 1$.

### 4.1. Origin of each parameter

The ADC128S022 datasheet is not in the repository, so only what the manual says is confirmed.

| Item | Origin |
| :--- | :--- |
| Four pins, 12 bits, 8 channels, 50 to 200 ksps, 3.3 V | Confirmed by the DE0-Nano manual (section 3.6) |
| Mode 3, 16-bit word, address in bits 13:11, four zeros ahead of the result | Not confirmed; assumption of the controller and of the test model |
| One-frame delay between address and result | Not confirmed; the `channel_latency` parameter lets it be changed without touching the rest |
| Minimum time with the select high between frames | Not confirmed; the controller keeps at least two cycles |

## 5. Registers

| Word | Name | Access | Reset | Description |
| ---: | :--- | :--- | ---: | :--- |
| 0 to 7 | `CH0` to `CH7` | R | 0 | Bits 11:0, last result of the channel |
| 8 | `CONTROL` | R/W | 0 | Sweep and interrupt (table below) |
| 9 | `STATUS` | R/W1C | 0 | Sweep state (table below) |
| 10 | `DIVIDER` | R/W | section 3 | Bits 15:0, ADC_SCLK clock divider |

| `CONTROL` bit | Name | Meaning |
| ---: | :--- | :--- |
| 0 | `ENABLE` | Continuous sweep; when cleared, the sweep in progress ends and stops |
| 1 | `IRQ_ENABLE` | Interrupt while `SWEEP_DONE` is 1 |
| 2 | `START` | Writing 1 starts one sweep with `ENABLE` at 0; always reads 0 |

| `STATUS` bit | Name | Access | Meaning |
| ---: | :--- | :--- | :--- |
| 0 | `BUSY` | R | A frame is requested or in progress |
| 1 | `SWEEP_DONE` | W1C | A sweep ended; a new event wins over the clear |
| 2 | `VALID` | R | A whole sweep has ended since reset |

The `o_irq` output is level-sensitive and equals `SWEEP_DONE` with `IRQ_ENABLE`.

## 6. Use by software

The C example turns on the continuous sweep, waits for the first sweep and converts channel 0 to millivolts. The conversion uses the 0 to 3.3 V range of the manual demonstration, so $V = \text{code} \cdot 3300 / 4096$ in millivolts.

```c
#include <stdint.h>

/* Base of the peripheral, defined by the platform. */
#define ADC_BASE ((volatile uint32_t *)0x40001000u)

enum { CH0 = 0, CONTROL = 8, STATUS = 9, DIVIDER = 10 };
enum { ENABLE = 1u << 0, IRQ_ENABLE = 1u << 1, START = 1u << 2 };
enum { BUSY = 1u << 0, SWEEP_DONE = 1u << 1, VALID = 1u << 2 };

#define ADC_FULL_SCALE_MV 3300u

/* Turn on the continuous sweep and wait for the first whole sweep. */
void adc_start(void)
{
    ADC_BASE[CONTROL] = ENABLE;
    while ((ADC_BASE[STATUS] & VALID) == 0) {
    }
}

/* Return the last 12-bit result of the channel (0 to 7). */
uint32_t adc_code(unsigned channel)
{
    return ADC_BASE[CH0 + channel] & 0xFFFu;
}

/* Convert the result of the channel to millivolts. */
uint32_t adc_millivolts(unsigned channel)
{
    return (adc_code(channel) * ADC_FULL_SCALE_MV) / 4096u;
}

/* Run a single sweep without staying in continuous mode. */
void adc_sweep_once(void)
{
    ADC_BASE[STATUS] = SWEEP_DONE;
    ADC_BASE[CONTROL] = START;
    while ((ADC_BASE[STATUS] & SWEEP_DONE) == 0) {
    }
}
```

## 7. Verification

The entity test connects the controller to a converter model that checks the 16-clock frame, the address of each channel and the chip select, and returns eight known voltages. The cases cover the idle pins, one sweep with the nine frames and the reading of each voltage, the continuous sweep that follows a changing voltage, the interrupt and the ADC_SCLK limit. The model repeats the assumptions of section 4.1 and marks them in the code. The sweep machine test runs with `channel_latency` 1 and 0 and checks the registers, the single and the continuous sweep, the stop with `ENABLE` cleared and the interrupt. The formal proof checks the frame (chip select, 16 edges, channel address on ADC_SADDR, completion pulse) and the sweep machine (channel asked, nine frames, result in the right channel, state, flags and interrupt), with mutants it must reject. Reading a known voltage on the board depends on a bench test.
